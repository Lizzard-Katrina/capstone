# 执行流程

请按以下顺序进行。每一步先说明你要做什么,再执行,再记录真实结果。

## 第一步:识别
- 查看仓库根目录,找出依赖文件,记录用的是哪一个。
- 找出所有可能的入口脚本(顶层含 argparse 或 `if __name__ == "__main__"` 的 .py 文件),
  **全部列出,不要只挑一个**。
- 读取 README,提取其中给出的可执行命令。

  > **约束**:如果 README 没有具体命令(例如只写"详见论文"),记录为"无可提取命令"。
  > 不要自己编造应该跑什么命令。

- 记录当前环境是否有 GPU(若已装 torch,用 torch.cuda.is_available() 检查;否则记为未知)。

  > **约束**:仓库是只读的,你没有写入权限。全程不要修改代码、依赖文件或配置,
  > 也不要创建补丁。若写入被拒绝,如实记录这次尝试,不要绕过或重试。

## 第二步:安装依赖
- 按识别出的依赖文件原样安装,记录安装命令、退出码、日志末尾。

  > **约束**:严格按依赖文件原样安装。不要额外安装依赖文件里没有的包,
  > 不要擅自修改版本号来解决冲突。安装失败就如实记录失败,不要通过换版本绕过。

- 不论成功与否都进入下一步,不要因为安装失败就放弃整个诊断。

## 第三步:逐个测试入口脚本
- 对**每一个**入口脚本分别测试:用 argparse 的执行 `python 脚本名 --help`;
  不像命令行脚本的则尝试 import 对应模块。
- 每个脚本单独记录结果,不要合并成一个笼统的"仓库通过/失败"。
- 若报错含 CUDA / GPU 相关内容,标记为 hardware_limited,不归入普通失败。

  > **约束**:每个结论都必须对应一次你真实运行过的命令及其真实退出码。
  > 禁止仅凭代码看起来没问题就下结论。

## 第四步:尝试 README 命令
- 对提取到的每条命令限时运行;卡住超时就中断,记为 timeout。
- 若已产生正常输出之后才因缺文件/缺模型权重报错,记为 data_boundary,**算作通过**。
- 若几乎没有输出就报错,记为 failed 并记录报错类型。
- 若第一步记录了"无可提取命令",这一步标记为 not_applicable。

  > **约束**:不要下载数据集或模型权重,不要生成假数据替代缺失输入,
  > 不要跳过检查直接假设某一步会成功。对同一个失败点最多重试 2 次。
